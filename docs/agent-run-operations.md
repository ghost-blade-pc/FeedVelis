# Agent 回合执行与恢复

API 内的有界 supervisor 执行回合，模型不属于 readiness 依赖。`agent.enabled` 开启而生成关闭或模型配置不完整时，历史、查询、取消、幂等重放和过期维护继续可用，新接受返回 503。默认最多同时执行四个回合；数据库仍统一限制每账户两个、每会话一个活动回合。

接受时固定 deadline（默认 60 秒），排队和重连均不延长它。领取产生随机 owner_token 与十秒租约，每两秒续约。业务动作和写入均检查原登录会话、当前账户、执行权与 deadline；执行器每秒检查共享状态。访问令牌的自然到期仅结束当前订阅，注销、账户禁用或会话删除才撤销执行授权。

关闭页面或 SSE 断线不会停止生成。停止须调用 `POST /api/v1/me/agent/conversations/{id}/runs/{run_id}/cancel`；终态取消仍返回 200。取消与成功按先提交者生效，失败片段只是 partial，不产生助手消息。刷新后先读取详情，再续读原回合；不要以新幂等键重新生成。

API 优雅关闭先停止新接受、领取并取消下游，再等待短事务写入 failed/AGENT_EXECUTOR_STOPPED、释放预留，最后关闭依赖。数据库先停时终态提交可能失败：恢复数据库后 supervisor 每秒维护最多 100 个候选，租约失效的 running 回合变为 failed/AGENT_EXECUTOR_LOST，绝不自动重新执行；accepted 超过 deadline 则 timed_out。重启先收敛过期事实，随后开始领取。真实 PostgreSQL 测试覆盖双执行器、取消/成功竞争、故障回滚、响应丢失及数据库连接池先关闭。

崩溃恢复步骤：恢复 PostgreSQL，启动支持当前 schema 的 API，查询原回合，等待租约过期及维护收敛；终态失败后才用新的幂等键和 `retry_of` 指向原回合重试。每条 user 消息最多三次尝试且最多一次成功。不能把 running 改回 accepted 或延长 deadline。事件和失败工作材料在终态 24 小时后有界清理，成功回答和引用身份保留。

回退前先关闭生成并等待活动回合全部终态，保留 000013 的表与事实，使用理解活动预留及生成助手历史投影的兼容二进制。旧二进制若忽略预留可能突破配额，若直接读取助手原文可能绕过引用失效投影，因此不得直接降级到不理解这些规则的版本。有事实的 down 会拒绝执行；不得删除用户数据来绕过此保护。需要数据库回滚时先做完整备份，并在隔离副本验证恢复；正常功能回退使用配置关闭生成即可。
